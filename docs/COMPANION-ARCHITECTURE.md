# Implemented architecture

`Emmy.Core` contains wire contracts, identities, conversation keys, action policy, cancellation lifetimes, the atomic request budget and a typed DeepSeek adapter. It has no Dalamud dependency. `Emmy.Host` owns SQLite, keys, conversation decisions, scopes, drafts, itinerary progression and the loopback API. `DalamudEmmy/Companion` contains the outgoing bridge, copied game state, bounded executor, native menu readers, foreground capture and compact UI. `Emmy.Replay` validates recorded action policies offline; it has no game or HTTP adapter.

The plugin exchanges a protocol-1 snapshot and bounded message/result batches every 500 ms. It retries unacknowledged events; message IDs are deduplicated by SQLite. Dispatched actions are not replayed after an unknown outcome. A fresh host epoch or cancellation generation invalidates local work. The plugin stops locally on a missing heartbeat. The host reserves request budgets across conversational and visual calls. The current consumer processes chat events sequentially; per-thread parallel scheduling remains an optimization.

Game reads, native calls and IPC happen on `IFramework.Update`, separate from drawing. Network operations never retain native pointers. World/client generations expire entity references. Tell keys include both player identities. Party keys include the captured membership set; Say keys include territory and local zone generation. Outgoing messages are recorded from client echoes, not invented from a successful dispatch.

A draft binds trigger, thread, recipient, config revision and cancellation generation. It expires and is consumed once. The model cannot call arbitrary game commands. The initial model action vocabulary is Follow, Interact and Capture; other bounded operator actions use the same policy and executor. Generic menu selection requires explicit local confirmation and a matching addon incarnation, prompt/options signature and enabled entry.

vnavmesh path queries use `Nav.PathfindCancelable`; only a current completed result reaches `Path.MoveTo`. Emmy avoids the SimpleMove auto-start path. Follow keeps a three-unit conversation distance, recalculates at bounded intervals and stops on target loss or lack of progress. Lifestream owns travel until the expected world/territory is actually observed or the outcome becomes unknown. Unsupported combat, cutscenes and loading states block new actions.

Memory is filtered by public/conversation scope before prompt assembly. Model-inferred facts enter as derived candidates. Only confirmed entries are facts in later prompts. Operator edits and forget invalidate open requests. A finite itinerary advances only after a succeeded result; failures/unknown outcomes stop the sequence. A meeting point contains observed coordinates, territory and world; visiting a point in another territory requires a separate verified journey.

The host uses user-bound DPAPI on Windows and an environment-only key on Linux. A random local capability, origin checks, exact Host checks, bounded requests, no-store API responses and a restrictive CSP protect the loopback surface. Debug exports intentionally contain conversation data, but no key. Data schema version 1 is the initial host schema; subsequent versions must introduce explicit backed-up migrations.
